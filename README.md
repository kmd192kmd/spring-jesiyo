## 1. 🏗️ System Architecture & Tech Achievement

### 🔹 슈퍼타입/서브타입 데이터 모델링
- **`auction_master` 도입:** 일반 경매와 라이브 경매의 PK(seq)를 묶어 슈퍼타입으로 분리했습니다.
- **확장성 확보:** 포인트나 결제 등 외부 시스템이 마스터 테이블의 PK만 참조하도록 설계하여 ID 충돌을 방지했으며, 향후 새로운 경매 타입이 추가되더라도 기존 구조를 유지할 수 있는 확장성(OCP)을 고려했습니다.

### 🔹 동시성 제어 및 성능 최적화
- **Redisson 분산 락:** 라이브 경매의 특성상 다수의 사용자가 동시에 입찰할 때 발생하는 최고가 입찰 로직 문제를 막기 위해 분산 락을 도입하여 데이터 정합성을 확보했습니다.
- **Redis 인메모리 캐싱:** 락 대기로 인한 성능 저하를 극복하고자 '최고가 조회' 로직에 인메모리 캐싱을 적용했습니다.
- **성능 개선 성과:** k6 부하 테스트(5,000 VU 기준) 결과, 에러율을 7%에서 1%로 낮추고 평균 응답 속도를 **약 390배 단축**시키는 성과를 거두었습니다.

### 🔹 쿼리 최적화 및 동시성 에러 해결
- **@Transactional 사용:** `@Transactional`을 사용하여 두 쿼리를 실행하는 경우 하나의 쿼리만 시행되는 일이 없도록 하여 데이터 정합성을 보장하였습니다.
- **락(Lock) 에러 해결:** `@Transactional` 동작 시 발생하는 오라클 락 에러 원인을 분석하고, 테이블 병렬 처리 비활성화(NOPARALLEL)를 통해 동시성 에러를 해결했습니다.
- **복합 인덱스 적용:** 경매 취소 로직 실행 시 대량의 경매테이블 누적 데이터의 status를 전부 조회하는 경우 발생 가능한 성능 저하를 방지하기 위해 `(auction_seq, status)` 복합 인덱스를 적용했습니다. 애플리케이션 계층의 쿼리문 수정 없이 오라클 옵티마이저(Optimizer)가 자체적으로 인덱스를 참고하게 됩니다.

## 2. 🤖 Retrospective: AI 시대, 개발자의 경쟁력
프로젝트 전반에 AI를 적극 활용하며, "코드를 생성해주는 AI 시대에 인간 개발자의 역할은 무엇인가?"에 대해 깊이 고민했습니다.

### "질문의 깊이가 설계의 수준을 결정한다"
AI는 구현 시간을 획기적으로 단축해 주었지만, 전체적인 시스템의 뼈대를 세우고 예외 상황을 시뮬레이션하는 것은 결국 **개발자의 집요함**이었습니다.

- **설계에 대한 집요함:** ERD 설계 단계에서 단순히 테이블을 나누는 것에 그치지 않고, "미래에 발생할 수 있는 극단적인 트래픽 상황"을 가정하며 팀원들과 치열하게 토론할 시간을 AI 덕분에 확보할 수 있었습니다.
- **문제 해결의 주체성:** AI는 답을 제안할 뿐, 그 답의 트레이드오프(Trade-off)를 인지하고 비판적으로 수용하여 우리 시스템 아키텍처에 부합하는지 최종 결정하는 것은 개발자의 몫입니다. AI가 짠 코드를 복사-붙여넣기만 한다면 장기적인 성장은 불가능합니다.
- **결론:** AI 시대에도 여전히 학습은 필요하며, AI의 의견을 무비판적으로 수용하지 않고 효율적으로 학습해 나가는 것이 필수 역량임을 느꼈습니다. 저의 경쟁력은 AI가 대체할 수 없는 **'본질을 파악하는 질문 능력'**과 **'최적의 구조를 설계하기 위해 끝까지 파고드는 집요함'**에 있다고 확신합니다. 

단순히 코드를 작성하는 사람을 넘어, 시스템의 철학을 정립하고 기술적 한계를 돌파하는 **주도적인 아키텍트**로 성장해 나갈 것입니다.
